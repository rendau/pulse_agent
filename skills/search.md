---
name: search
title: Поиск по номеру и логи
when: номер заказа, задания, клиента, телефон или другой идентификатор; ошибки в логах сервиса
---
Идентификатор без названного сервиса (номер заказа, id клиента, телефон, GUID) → query_logs без
service, pattern — сам номер. Он сам ищет назад по дням (search_stop — почему остановился);
конкретный день или время — в end. Ответ: services — где и сколько раз встречается, lines — строки
по порядку событий, id_matches — чей это объект по формату номера (раздел domain сервисов).
- Найденные строки — уже все следы по всем сервисам: не запрашивай их повторно по каждому сервису
  (разве что truncated).
- Телефон — в pattern с «+» (+77011234567): найдётся в любом написании. Токен pii:… передавай как есть.
- Дальше — у сервиса-владельца объекта (id_matches или по смыслу) ручка из diagnostic_endpoints
  карточки (get_service_info), например «где задание и почему стоит»: call_service_endpoint с номером.

Логи сервиса: query_logs service=…, level=error; по умолчанию ответы свёрнуты в паттерны (тысяча
одинаковых ошибок — одна строка со счётчиком). Если человек назвал workload сервиса (например
notifire-sms у сервиса sms) — сужай параметром workload. Ошибки без названного сервиса —
get_cluster_health (log_errors), не переспрашивай сервис.
